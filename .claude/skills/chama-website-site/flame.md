# The flame

- The watchdog's batch is capped (40 conversations, 400 KB). If anything was dropped, a `clear` verdict is raised to `concern` so the email still goes out. Flooding the window to push an attack out of review is a known trick.
- The Anthropic SDK never sets `error.name`, so every failure used to log as a bare `Error`. `describeError` in `api/chat.js` logs class, HTTP status and API error type. Keep using it.
- Hitting the account's API spend limit comes back as a `400` whose message mentions usage limits. `api/chat.js` treats that as the flame resting and shows the offline message, not a "try again".
- The fire runs in a Web Worker on touch devices because sharing the main thread with scrolling, the keyboard and streamed text made it jank on phones. Desktops run it inline.
- On touch, the embedded room is never a nested scroller. Engaging it pins it to the visual viewport as a sheet so a soft keyboard cannot push the layout off screen.
- The flame's `ANTHROPIC_API_KEY` is the Console key `chama-website-flame` (Chama Inteligente workspace, never expires). The Console defaults new keys to a 30-day expiry: the old key `chama-deploy` expired 2026-09-27 and the flame answered every visitor with "Something went wrong on our side" until 2026-11-01. A dead key logs `Chat agent failed AuthenticationError status=401`; check with `vercel logs --environment production --since 7d --level error -x`. Env changes need a new deployment to apply.
- The homepage loads `worlds.css` and `agent.css` together, and the chat marks each message `.turn`. A bare `.turn` rule for the /clients wheel hid every chat message from 2026-10-22 to 2026-11-01 while `/api/chat` answered 200. Scope page-section classes in `worlds.css` to their container; `test/pages.test.js` guards `.turn`. To test the chat in a browser, read `#transcript`'s computed opacity, not just its text.
- `lib/flame-health.js` exists because the five-week outage above went unnoticed: the watchdog reads conversations and never sees a flame that cannot talk. It probes `models.retrieve` (free) from the watchdog cron rather than sending a message, so it never spends credit. To see its last result, look for `flameHealth` in the watchdog's logs.
- The prompt was rewritten on 2026-11-11 around what the saved conversations showed: of 38, almost all ended after one reply, a visitor's few words got about 110 back, and one note had ever been sent. Replies are now sized to the visitor's latest message. Read real transcripts before touching the prompt (`vercel env pull` gives the blob token; list `chat/`), and never trust a model playing a visitor to get bored on its own: it sat through everything until patience was counted in code (`strikesFor` in `evals/simulate.js`).
- The flame once told a visitor "we don't do referral partnerships", a policy nobody wrote, in answer to the exact message the About page's link sends. A list of what the flame is for reads to the model as a list of what it is not for. The prompt now says it is the way in for everything and has no position on anything it was not given.
- Elliot, 2026-11-11: the call to action is simply "talk to us". The flame's offer uses those words.
