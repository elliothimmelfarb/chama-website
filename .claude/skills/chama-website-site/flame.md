# The "Talk to us" agent (still "the flame" in code)

- 2026-11-16 rebrand: the agent lost its flame persona and its `adjust_experience` tool. It is the "Talk to us" chat, speaks the brand language, and never gives out an email address or phone number itself (`api/chat.test.js` holds that for every message the chat can show). The only address on the site is `info@`, which the widget shows only when even the plain form has failed.
- The 2026-11-16 rebuild replaced the old widget (`agent.js`, `agent.css`, the fire in its Web Worker, the flame room on the home page) with `assets/talk.js`. The old widget's lessons about the embedded room, its scrolling and the fire are gone with it. `createChat()` in `talk.js` holds every decision without the DOM, so new behaviour goes there with a test in `test/talk.test.js`, and the DOM half is checked in a browser.
- Where the first reply's wait was (2026-11-16, measured in production with `/api/chat` timed from a script): about 1.1 s to the first word with a warm prompt cache, 1.8 s cold, and once 6.7 s on the first request of the day (a cold function or an API retry; it did not repeat). Real visitors arrive more than five minutes apart, so almost every first message was cold; the warm-up request fixes that. On the new prompt, Sonnet 5 at low effort was steadiest (median 1.08 s, slowest in ten 1.4 s); Sonnet 5.5 and Haiku 5.5 were quicker on "hey" but reached 2.2 s and 5.4 s on longer questions, because they think first. Measure before changing the model.
- Consent to be contacted is checked in code, not trusted to the model (`consentProblem`): the details must be ones the visitor typed and the agent must have shown them in the message right before the visitor's latest one. A visitor who changes a detail inside their "yes" gets the new version shown again rather than sent. The widget adds its own gate in front: the details form sends them as the visitor's message, and "Yes, send it" only appears once a reply shows every detail back.
- The watchdog's batch is capped (40 conversations, 400 KB). If anything was dropped, a `clear` verdict is raised to `concern` so the email still goes out. Flooding the window to push an attack out of review is a known trick.
- The Anthropic SDK never sets `error.name`, so every failure used to log as a bare `Error`. `describeError` in `api/chat.js` logs class, HTTP status and API error type. Keep using it.
- Hitting the account's API spend limit comes back as a `400` whose message mentions usage limits. `api/chat.js` treats that as the chat being offline (an `error` event with `kind: "offline"` inside a 200 stream), not a "try again". The widget decides by `kind`, never by the words, so rewording `MESSAGES` cannot break it.
- The chat's `ANTHROPIC_API_KEY` is the Console key `chama-website-flame` (Chama Inteligente workspace, never expires). The Console defaults new keys to a 30-day expiry: the old key `chama-deploy` expired 2026-09-27 and the chat answered every visitor with "Something went wrong on our side" until 2026-11-01. A dead key logs `Chat agent failed AuthenticationError status=401`; check with `vercel logs --environment production --since 7d --level error -x`. Env changes need a new deployment to apply.
- `lib/flame-health.js` exists because that five-week outage went unnoticed: the watchdog reads conversations and never sees a chat that cannot talk. It probes `models.retrieve` (free) from the watchdog cron rather than sending a message, so it never spends credit. To see its last result, look for `flameHealth` in the watchdog's logs.
- The prompt was rewritten on 2026-11-11 around what the saved conversations showed: of 38, almost all ended after one reply, a visitor's few words got about 110 back, and one note had ever been sent. Replies are now sized to the visitor's latest message. Read real transcripts before touching the prompt (`vercel env pull` gives the blob token; list `chat/`), and never trust a model playing a visitor to get bored on its own: it sat through everything until patience was counted in code (`strikesFor` in `evals/simulate.js`).
- The agent once told a visitor "we don't do referral partnerships", a policy nobody wrote, in answer to the exact message the About page's link sends. A list of what the agent is for reads to the model as a list of what it is not for. The prompt now says it is the way in for everything and has no position on anything it was not given.
- Elliot, 2026-11-11: the call to action is simply "talk to us". The agent's offer uses those words.
