# Pages and the worlds engine

- A section that is not a `.world` (the `/clients` ledger) scrolls under the fixed header, which has no background of its own. Pinned worlds never showed this because their words sit low on the screen. `/clients` gives the header a strip of paper with `html:has(main .ledger) .top::before`; any new scrolling section needs the same.
- The router (`worlds.js`) scrolls to a link's `#hash` itself, so CSS `scroll-margin-top` is ignored unless the router reads it (it does since 2026-10-22), and `pushState` never moves `:target`. An entry reached through the router gets `.is-target` instead; style both.
- A new animated page joins the router through `PAGES` in `worlds.js` and needs a `/simple` twin, both navs, the sitemap and `llms-full.txt`. `test/pages.test.js` holds the pairs and the nav labels.
- Client logos in the heroes are ink, not colour: `grayscale(1) brightness(0.62) contrast(1.5)` with `mix-blend-mode: multiply`. Plain `grayscale` makes gold marks (Alves) nearly vanish on paper.
- A logo a company draws in code (inline SVG plus a web font) is best captured from its own site with Playwright at `deviceScaleFactor: 4` and `omitBackground`, after clearing the backgrounds up its ancestors. Check the result for a leftover background box: Alves's header kept one, removed by keying out its colour.
- This repo is public, so a client's name or logo is published the moment it is committed and pushed, before any deploy. Keep a listing local until that company has said yes in writing.
- A drawn figure (`kind: "draw"`) is painted on the fixed canvas at its layout every frame, and only fades when a next world arrives. On a page whose last world is followed by ordinary content (`/clients`), it would stay on screen over that content. `drawWheel` moves its outline up with its section's pin, from `pinEnd` (where `measure()` found the pin starts to leave), not from the pin's rect; a new figure in the same position needs the same.
- The `/clients` wheel (`drawWheel` in `worlds.js`) is an upright ring seen from its right: it sets each `.spoke`'s transform, depth dimming and `z-index` every frame and toggles the `.turn` in focus. There is no separate script, because the router swaps `<main>` and scripts inside it never run. It stands on the light grid world on purpose: without plates, dark logos (Toraya Lisboa, Springlar) vanish on a dark ground.
- Two text blocks crossfading in the same grid cell read as a double image mid-turn. The outgoing `.turn` leaves in 0.18s and the incoming one waits 0.2s.
- A link to a client on the wheel (`/clients#springlar`) must scroll to where that client is in focus, not to the element, which sits in a sticky pin. `anchorY()` (through `pinnedY`, `wheelY`, `devicesY`) does this for the router, same-page links, `hashchange` and a fresh load, and `wheelY` for spoke clicks; on a fresh load it runs again after `load`, because the first measure comes too early.
- Loading `/clients#springlar` makes the browser scroll the clipped `.pin` itself (by about 90px) to reach the anchor, since `overflow: hidden` boxes still scroll programmatically. Everything inside the pin moves while the canvas does not, so the ember outline sat below the logo. `toHashTurn` resets `pin.scrollTop`; any new anchor inside a pin needs the same.
- The wheel's last place holds for `WHEEL_HOLD` of the scroll before the next world arrives. Without it the last client, or the open "Yours?" place, came into focus just as the pin started scrolling away.
- `/work` became `/clients` on 2026-10-26 and Friends moved to `/about`. The friends directory is a world with an empty pin (`.directory`), so it can stand on any dark world; on About it is the forge, because Elliot's section just before it is the night, and two sections on the same world in a row would not get the fire's handoff between their figures. The header strip behind it is keyed to that world's theme (`.top[data-theme="forge"]`).
- Since 2026-10-27 the friends directory is one screen tall on desktop (`min-height: 100svh`): the heading, deck and note on the left, the letters on the right (`.dir-list`, spanning both rows). On a phone it stacks and the note moves under the letters. A logo plate inside a flex row needs `rem` padding, because percentage padding resolves against the row's width, not the plate's, which shrank the TLC mark to a speck.
- On a phone the hero's figure only gets the room left between the header and the top of the words (`stackOf` in `worlds.js`), so every line added under the deck takes it from the shape. When the logo rows gave each label a 44px row, a 664px-tall phone left the shape 33px and it was drawn over the heading (2026-11-01). The phone block keeps the logo rows tight, and the figure may shrink to 0.22 of its size on a short phone instead of overlapping. Check 390×664 and 375×548 after adding anything to the hero.
- Elliot's phone renders the site at about 364×610 CSS px with text at roughly 106% (Chrome's font size setting). Emulating it in Playwright takes `Page.setFontSizes` through CDP (standard 17). Check every page at that size with that font before calling mobile work done. A plain 390-wide emulator hides most of the crowding.
- On a phone the header is a grid of two rows: the lockup, Members and the motion switch, then the pages. Past the opening world (`.head-compact`, set in the frame loop) the first row fades and the pages rise by `--head-lift`. `stackOf` gives every later world that height, and the `/clients` wheel world gets it almost at once. A strip behind the header (`.top::before`) has to subtract `--head-lift` too.
- What rides up with a leaving pin is gone before it reaches anything (2026-11-11), and dissolves rather than blinks (2026-11-12). The drawn figures on the fixed canvas do not ride up at all, except the last world's, which rises with the page's tail (`st[3]`) and leaves first (`markGone`). The tail is for the last world only: when the one-column fire line went into `scrollState` as a second `if`, the tail's `else` bound to it, every world had a tail in the pinned layout, and every figure rode up under the header (the homepage pentagon on a phone, 2026-11-12). `goneOf` in `worlds.js` measures, per world, how many pixels past the pin's release the first thing in it can go before it reaches the header, or, for words under a figure on the fixed canvas (a phone, the last world at any width), that figure. The fade ends there but lasts at least `EXIT_MIN` (0.15) of the screen, so where the room is short it starts in the last of the hold. Ending it at `--gone` alone left 10 to 30 px of fade on every phone handoff and the 1280x720 heroes: a blink at any real scroll speed (the design review's blocker). Moving the end point instead would let words reach the header. `exitOf` works out what is left (1 to 0; a unit of `--u` is a screen once the pin lets go, the hold's length before, so the fade is even per pixel across the release): `setU` writes it as `--e` beside `--u` on the words and the shade, and it sets `/built`'s stage and bar (an opacity and a 16px drift from `drawDevices`), the wheel and the last world's mark. `.r` already drifts up 16px as `--e` falls. The last world counts on past its end, but only as far as the footer: what that tail never carries into the header keeps no fade (`reach`), or the floor faded the mark in place at the foot of `/built`. A fixed `--out` could not do this: at 1.35 desktop words slid under the lockup, and the scrim fading only at 1.45 left its clipped edge on screen as a hard rectangle at every handoff on a phone. Something new that rides in a pin (a DOM figure, a plate) belongs in `goneOf`. Captions sit inside their figure's reach and end their fade at once (`CAP_GONE`). The last world's mark (and the sky's flame with it) has its own, earlier exit (`markGone`), so the words below it are not cut short. Judge an exit from frames 0.2 of a screen before each release to 0.3 after, at 364x610 (font 17), 390x664, 375x548, 1280x720 and 1440x900; a static screenshot of the end of the page clamps to the last scroll and hides the tail.
- A drawn figure in a box (`scene.box`) never goes below 0.4 of its size: under that, its labels collide. `drawCurve` moves CHASING above the bursts when the box is short. The about prints are capped by `--fig-h`, the figure's height, so they never reach the words.
- `/privacy`'s "Where it goes" has a second, vertical SVG for phones (`.fig-flow-tall`), because the wide one's words shrink to about 5px there. Change both when the flow changes.

- `/built` (2026-11-11) is one pinned world, like the `/clients` wheel: `drawDevices` in `worlds.js` toggles classes and scrolls the pictures, because scripts inside `<main>` never run after the router swaps it. Lessons from building it:
  - Cross-fading two identical device frames thins the bezels halfway. The outgoing rig stays fully opaque underneath (`.rig-was`) until the new one has faded in, and must then be removed: left in place it showed behind the next thing wherever the two rigs differ in size.
  - On a phone the devices are one size for every thing (`--fit` on the stage, set by `devicesFit`): as large as leaves the longest words clear of the progress bar and the opening words clear of the first rig. A size per thing made the devices jump between things, which the design review caught. Measure with `offsetTop`, not `getBoundingClientRect`: the hidden words carry a slide. Before the first scroll the header still has its lockup row, so the rig stands lower by `--head-lift` until `.head-compact`.
  - The pictures after the first are `data-src`/`data-srcset`, set when their thing is next, with a `<noscript>` copy. All sixteen up front is 2.2 MB. The router parses pages with scripting off, so those `<noscript>` images are real elements after a page swap: select `.screen > img`. The things either side are fetched only once the pair on the screens has arrived (`devicesLoad`): fetched together, the next pair took half the bandwidth of a phone's first screen and LCP was 4.7 s on slow 4G.
  - Desktop pictures are 1800 wide. At 1100 the laptop screen was soft on a 2x display. Phones get copies (640/960/1200/1440 and 160/240/320 wide, recipe in the README) through `srcset`: the 1800 master is 32 MB decoded and a phone shows it 200-330 px wide.
  - Chrome (157, installed) picks the smallest `srcset` copy whose density reaches the screen's DPR, unless a copy already in its cache reaches it, which it takes instead. So a `sizes` that overstates loads a step larger, one that understates loads a softer one, and a picture shown in two places shares a fetch only if each place lists the other's copy and that copy is dense enough there. Playwright's bundled Chromium picks differently (the smaller of two copies when the DPR is under their densities' geometric mean), so check picks in the installed Chrome (`executablePath`), as the rigs do. A lazy image takes `sizes="auto, ..."`, which Chrome resolves from its laid-out width: `/simple/about`'s founder photo at `15rem` loaded the 900 master on a phone with a 17px font, where it is shown 240px wide.
  - Alves Teamwear's desktop picture was 1100 wide. It was recaptured on 2026-11-11 from teamwear-studio's local dev server at a 1100 px viewport and `deviceScaleFactor` 1800/1100, so the layout matches, with every email address on the page replaced first: the old one showed a real address in the activity list. A recapture gets a new file name (`-desktop-1800.webp`): old picture URLs are cached outside our control, so files already published stay in place.
  - On desktop every thing's words start on the line of the laptop's top (`--made-top`). Centring them made the title jump with the length of the text.
  - The last thing's pictures move until the pin lets go (2026-11-12, Elliot: "on the built devices the apps stop scrolling for a little bit before the page scrolls and I'd like there not to be that pause. The moment the devices stop scrolling the page should scroll."). The pictures used to ease to a stop at 90% of the thing and a `DEV_HOLD` of 5% of the world followed, so 53vh (phones) to 65vh (desktop) of scroll moved nothing before the exit fade began. Now the last thing runs on `devicesLast`, a curve from rest that ends with the laptop's picture moving at the page's own speed (its end slope is the thing's scroll over the picture's room), so the picture inside the screen hands over to the devices riding up with no change of speed; the exit dissolve plays over the moving picture. Matching speed matters as much as removing the dead stretch: ending on a smoothstep would still slow to a stop under the finger. The joins between things keep their rest (about 13vh after and 10vh before each swap, with the words and rig changing in the middle): that is a beat to read, and something answers in it. Measure it as numbers, not by eye: scroll in even steps and print the picture's offset and the stage's top and opacity, so a run where nothing changes shows up as a length.
  - The things not showing are `inert`, so the progress bar's bars are links to each thing: without them nothing on the page was reachable by keyboard.
  - The scrim (`.pin-shade`, first in each pin) is positioned, so it paints over unpositioned content in the pin: as the pin's `::before` without JavaScript it washed the list out until hidden.
  - Five links fit the phone header only with the tighter `.nav-link` padding in the phone block. Check `/coaching` too: it also carries Members.
  - A capture of a signed-in app comes from that project's seeded local server (VSF: `npm run build && PORT=3417 npx tsx scripts/dev-seed.ts`, then its `scripts/shots.ts`), so no real lead is ever in a picture. Show the thing we built, not the client's own website: the first VSF pictures were of the Alves landing page, which we did not make.
  - ffmpeg here has no WebP encoder. Chrome's canvas `toDataURL("image/webp")` through Playwright does the conversion.
- The router's page change (2026-11-11) is timed so a phone can read the new heading about 0.7s after the tap and everything is still by about 1.2s: `LIFT` (0.2s, measured from when the words began to leave, so a second tap never restarts it), `BURN` (0.85s, ease-out) and the `rise` keyframes, all in step with the comment above `.nav-leave`. Lessons from tightening it:
  - The shader's fire line starts 0.4 of a screen below the bottom and its flames reach about 0.3 above the line, so a burn from mix 0 spends its first quarter off screen. `MIX_FROM` starts it where the flames first touch the screen.
  - The real floor on "readable" was the hero's fresh-load fade (`.hero .copy`, 1.4s), which ran again on every swap because the hero is a new element. `html.routed` turns it off once the router has swapped a page in.
  - Anything in `.nav-enter` must end inside `BURN`: the class goes when the burn ends, and an animation still running then jumps to its end.
- The router measures a swapped-in page only once `.nav-leave` is gone (2026-11-12): it lifts `main` by 2.5vh, and `translate` does not change `scrollHeight`, so the ResizeObserver never corrected the cached positions and /clients' `at-end` came 20px early until a resize. A page the router leaves by a full load (another deploy, a failed or hung fetch, the motion switch) goes into the back/forward cache mid-change; `pageshow` with `persisted` settles it, or Back shows a blank page whose tapped link is ignored.
- The router leaves `#` links to the browser, and the browser does not scroll to an anchor inside a sticky pin, because it is already "in view". The page-level click listener sends a same-page `#` link whose target has a `pinnedY` there itself (the /built progress bar), and `hashchange` runs `toHashTurn` for Back and Forward.
- A spoke takes a tap only on its logo (`.spoke` is `pointer-events: none`, its `img` and `.spoke-mark` are `auto`). The spoke's box is a square round the logo with the client in focus on top, and on a phone ring (`rx` about 0.145 of the width) that square covered the logos behind it at every place of the wheel. Check taps by `elementFromPoint` at each visible logo's centre across the whole wheel at 364x610 (font 17), 390x844, 375x548 and 1440x900.
- Each page that dissolves into the next opts in with an inline `<style>` under its `<title>` (2026-11-12). Chrome settles the cross-document view transition opt-in as it starts the body, so an `@view-transition` in a stylesheet still loading counts as none: on a slow load (and on `/simple`, whose `site.css` comes after its scripts, about half the time even locally) the dissolve was skipped with "ViewTransition opt-in disabled". Test it by logging `pagereveal`'s `viewTransition` from an init script, with CDP network throttling, never Playwright's `route()`, which aborts every cross-document transition.
- Pressed states use the `scale` property, not `transform`: it composes with the transforms `worlds.js` writes every frame (the spokes) and those a control already has. `--press` in `worlds.css` is the release.
- The animated pages' speculation rules leave out the router's five pages: a speculative prefetch goes to its own cache, not the HTTP cache the router's `fetch()` reads, so both would fetch the page. Every page's rules list the pages they are for (2026-11-12, from the security review): a prefetch carries cookies, and `/*` reached GETs that change state, such as a magic link's callback, which spends its token and signs in. A new public page joins the lists; `test/pages.test.js` holds them to never reaching `/api`, the Hearth's inner paths or an unnamed path.
- Anything written every frame must land on the elements that read it. `--wipe` on `<html>` restyled the whole document each frame of the burn (about 10ms a frame at 4x); on the arriving pins, registered `inherits: false`, the frame loop's whole frame dropped from about 16ms to under 5ms at 4x.
- Chrome scores LCP when an element first paints with any opacity, and an element that starts at `opacity: 0` is scored when it shows. The hero's logo row caught like embers from 0, so the last logo, 2.1 s in, was the LCP on `/` and `/coaching` though the words were readable at 0.2 s. Entrance keyframes start at 0.01, which looks the same (`test/pages.test.js` holds `arrive` and `catch` to it).
- `html.js` is the pinned layout, not "JavaScript is on". Every page styled by worlds.css sets it in its head before the first paint, as its script will later (worlds.js is deferred; waiting for it painted the no-JS layout first and on `/built` drew eight things' words over each other; the 404 left it to sparks.js and shifted by 0.063 until 2026-11-12, so the test finds every such page itself). The animated pages leave it off under 500px of height. There, without JavaScript, and in print (`beforeprint`), the worlds are one column of sections under the same sky (the "one column" block at the end of worlds.css). The head and `worlds.js` must use the same media query; `test/pages.test.js` checks it. Never `display: none` the `#actors` canvas: `worlds.js` sizes everything from it (a zero height turned every `--u` into NaN and the sky black). In one column `layFlat()` (on every layout change and `beforeprint`) undoes what the pinned choreography applies, because the frame loop's state was written for a pin that is not there: /built's things un-inert, every picture given its `src` lazily (eagerly for print), /clients' entries not `aria-hidden` (never in the markup either, so JavaScript off reads them), and pictures without their scroll. The loop then paints only the sky. Back in the pinned layout, `D.words`, `D.rig` and `W.on` are reset so the loop applies its state from scratch. Anything new the loop toggles on a pinned world (inert, aria-hidden, a class that hides, a style written with `put()`, which `unput()` takes back) needs its undo there.
- One column has no pinned positions (2026-11-12, two regressions found in production an hour after the campaign that introduced short-screen one column):
  - `wheelY` and `devicesY` answer `null` outside the pinned layout, and every scroll to an anchor goes through `anchorY()`, which then falls back to the anchor itself. `toHashTurn` had scrolled to the pinned place, which in one column is the section's top, so every link to a client or a thing landed at the top of the page after the browser's own jump. A new "where is this in focus" helper must answer `null` there too.
  - Every `html:not(.js)` rule now applies to short screens and print as well as JavaScript off. `html:not(.js) .wheel { display: none }` took every logo off /clients on a phone held sideways. Before writing one, ask what a visitor with JavaScript on sees at 610x364.
  - The /clients wheel lies flat there: `.copy`, `.turns` and `.wheel` are `display: contents`, so the turns and spokes are items of one grid on the pin, and `grid-auto-flow: dense` puts each spoke in the first free row of the logo column, its own client's. The intro spans both columns. A new client needs no new rule; `test/pages.test.js` holds every client to a logo and no one-column rule to hiding the wheel.
  - Check one column at 610x364, 844x390 and 640x360 (fresh load with a hash, through the router, Back and Forward, the /built bars) and with JavaScript off at 364x610 and 1440x900. Resize from the pinned layout to one column and back too: that is where `layFlat` has to undo the loop's state.
- Past 120rem the worlds keep to a centred stage (`--stage`, `--side`, `--edge` in worlds.css; `SW`, `SX` and `sx(f)` in worlds.js). A desktop figure is placed with `sx()` and sized with `SW`, never `AW`, or it drifts off the words on an ultrawide.
- Labels drawn on a chart clear what is under them (`clearLabel`), as on the team chart, rather than being nudged around lines that move with the box's size.
- The low motion pages carry the animated header's five pages in their masthead, held still (no thumb), under the lockup on every size; the lockup links to `/simple`. Every `:hover` sits under `@media (hover: hover)`, and one `:focus-visible` rule sets the ember ring in worlds.css and site.css.
- The cost of a scroll frame (2026-11-12, measured with the jank rig on 364x610 at 4x and 6x CPU):
  - A custom property written on an ancestor every frame restyles its whole subtree, because unregistered ones inherit. `--u` is registered `inherits: false` and written on its readers (`U_READERS` in `worlds.js`); a pseudo-element takes it with `--u: inherit`. A new rule that reads `--u` must sit on a reader or join the list, and `test/pages.test.js` fails if it does not. Any new per-frame variable wants the same treatment.
  - Never make a container a reader: Chrome restyles everything inside an element whose `--u` changes, inherited or not, `--u: inherit` below it or not (2026-11-12, measured both). The scrim was the pin's `::before`, so the pin was a reader and every frame restyled the whole of both worlds in view: 52 elements a frame on `/` against 43 before per-reader `--u`, and style a frame at 6x up from 3.2 to about 4.5 ms. The exit's `--e` was the suspect and was not it: without it the count did not move. The scrim is now an element `bind()` puts first in each pin, `.pin-shade` (the 404 has it in its markup), and the test holds pins, worlds and the words' boxes out of `U_READERS`. Not `.scrim`: the chat, inside `<main>` on the homepage, already has one, and took the worlds' width and one-column `display: none` (caught in review; the test now checks readers' classes against the chat's).
  - Bisect style cost by how many elements each frame restyles, not by milliseconds: sum `elementCount` of the `UpdateLayoutTree` trace events over a fixed touch scroll and divide by animation frames. It is the same on a quiet machine and a loaded one (to within a few percent run to run), where the milliseconds swung 30%.
  - The loop reads no layout. `scrollY`, `getBoundingClientRect`, `offset*` and `scrollHeight` inside a frame each finish all pending style first, including the chat's streamed words. Positions come from `measure()` (reads first, then writes), the scroll from its event, and a ResizeObserver re-measures a page that grows. A sticky pin's top is arithmetic (`pinEnd`). `drawFamily` and `drawPeer` on /about still read their card's rect after `setU`, because the card's slide is part of where the lights go; that flush now costs only the `--u` readers.
  - Removing the reads alone gained nothing in the audit: the style work just moved. What it costs is how many elements a write invalidates, so cut that first. That paid where a world holds much more than its words (/built 7.9 to 1.9 ms of style a frame at 6x, /clients' forced style 4.4 to 0.8), and nothing on /, /coaching and /about, where nearly every node is a `.r` and restyles anyway: there the cost (about 2 to 4 ms at 6x) is each `.r` resolving its `var()` chain into opacity and transform. Registering `--a` and `--b` as numbers did not lower it. The next lever there is fewer readers changing per frame, not cheaper writes.
  - A still page draws every other frame at 120 Hz (`STILL_MS`, `AMBIENT_MS`). Anything new that must move on every frame while the page is still has to mark itself as motion in `stirred()`.
  - `devicesFit` halves its thirteen sizes. That relies on the words fitting better as the devices shrink; if a layout breaks that, it lands on a different size than a linear walk would.
  - To prove a change looks the same, compare computed styles and screenshots under Playwright's fake clock (`clock.install` then `pauseAt`, seeded `Math.random`, CSS animations off). Fake rAF does not wait for the browser's scroll event, so wait a real moment after each `scrollTo`.
  - `--e` is written by `setU`, not worked out in CSS from `--u` (2026-11-12). As a CSS sum on every reader it was the same `exitOf` twice, and each reader resolved it on every frame though it changes only while its world leaves; written from JS, it is set only when it changes, and the style time per restyled element fell by about 10%. It is registered `inherits: false`, so it must be written on each element that reads it (the test checks every `var(--e)` rule is on a reader). Declared on `.world` it once sat at its initial value for ever and every exit fade stopped without an error.
  - Do not make a container a `--u` reader. `/built`'s `.made-stage` and `.made-ticks` as readers doubled /built's style time a scroll frame at 4x (1.5 to 3.4 ms; elements per recalc 5 to 13), because Chrome restyled what was inside them each time their `--u` changed, even with `--u` and `--e` not inherited. Their fade is an opacity `drawDevices` writes with `put()`, which writes nothing until the world leaves.
  - `measure()` reads, writes, then reads again: the exits (`goneOf`, `markGone`) and the room's and footer's places are where the writes put things (`--copy-b` places the words under a stacked figure, `--foot` moves the room). Its writes go through `setVar`, which skips a value that has not changed, so a re-measure that moves nothing (most ResizeObserver calls, a toolbar) costs one layout, not two.
  - A layout read in any script's animation frame counts, not only the worlds loop's: it runs after the loop has written that frame's `--u` and forces the style for it. `agent.js` checked the flame room's seat in a frame of its own on every desktop scroll; it now reads in the scroll event, where the layout is the one last painted. To find such reads, count the layout getters called inside `requestAnimationFrame` callbacks while scrolling: wrap `requestAnimationFrame` and the getters (`getBoundingClientRect`, `offset*`, `client*`, `scrollY`, `getComputedStyle`) in an init script.
