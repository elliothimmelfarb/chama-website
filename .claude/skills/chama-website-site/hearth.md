# The Hearth

- The Google Auth Platform app is published but unverified (2026-09-02). The owner sees Google's "unverified app" screen once when connecting, and at most 100 users may grant the sensitive scopes before verification.
- The original `GOOGLE_CLIENT_SECRET` cannot be viewed again. If it is ever needed, add a new secret on the client in Google Cloud (project `chama-website-admin`).
- Discord sign-in is built but its credentials are not set (2026-09-02): the Discord developer portal needs a captcha only a person can tick. The button appears once both variables exist.
- `ADMIN_EMAILS` is a Sensitive variable, so `vercel env pull` returns it empty and it cannot be read back. Since 2026-10-13 it is `elliothimmelfarb@gmail.com,elliot@chamainteligente.com`. To change it, `vercel env rm` then `vercel env add --sensitive`, then redeploy production; the old value is lost, so write the whole list.
- Until 2026-10-13 a closed signup (`open_signup` off) also refused an admin address with no account yet. `mayEnter` in `api/hearth.js` now lets `ADMIN_EMAILS` through every door.
- Preview deployments share the production database (`DATABASE_URL` is set for Production, Preview and Development). A preview is not a sandbox for Hearth data.
- Claude operates the Hearth through the `chama-hearth` MCP server in the user-level Claude Code config, with an API key named "Claude Code (Elliot's machine)" on `elliot@chamainteligente.com`. The secret is in the macOS Keychain, service `chama-hearth-api-key`. Revoke it in the Hearth under Agents.
- For a direct database query, `vercel env pull` into the scratchpad gives `DATABASE_URL`, and `@neondatabase/serverless` from this repo's `node_modules` runs it. Run the script from the repo root so the import resolves, and never commit the env file.
- Writing a crafted record: `add_transcript` with `draft: true` (no model, no mail), then `set_record_figure` per picture, `set_record`, `set_record_cards`. None of them email the member; the invite does. First one: Scott Nelson, session 1, 2026-10-13.
- Record figures render at about half size on a phone (600-unit viewBox in a ~340px column). Draw at 600 wide with body text at 17 or more and labels at 14 or more, and check them as PNGs with `qlmanage -t -s 900` before uploading.
- A browser that loaded the Hearth before a deploy keeps the old `hearth-*.js` for up to ten minutes, so a new record can render in the old layout. Fetch the assets with `cache: 'reload'` before judging.
- Billing modes (2026-10-15): every member defaults to pre-buy (`users.billing = 'prebuy'`); flip one to billed after on their member page. Bookings carry their own `billing` ('credit', 'after', 'free') so a member changing mode later does not rewrite history.
- To see the Hearth with data locally without touching production, run the real `handleHearth` against PGlite (`@electric-sql/pglite` installed in the scratchpad, never in the repo), apply `MIGRATIONS` statement by statement, seed users and `login_sessions` rows with `hashToken("tok-...")`, and set the `__Host-chama_hearth` cookie in the browser. Chrome accepts `Secure` cookies on `http://localhost`. PGlite returns `Date` objects where Neon returns strings; convert them to ISO strings in the adapter.
- In the availability grid, cell heights must be whole pixels. Fractional heights (1.05rem) leave visible seams inside painted blocks.
- Google busy time (2026-10-15): `calendar.events` already lets the Hearth list events on any calendar the connected account can see, so reading needed no new consent. `freeBusy.query` would have needed a new scope (`calendar.freebusy` or wider), which is why events are listed instead. The connected account is elliot@chamainteligente.com; on 2026-10-15 it could see only its own calendar and "Holidays in Portugal", not the personal Gmail calendar. Adding that one needs Elliot to share it with the Chama account, then add its address under Availability, Calendars.
- The local dev harness can fake Google by stubbing `globalThis.fetch` for `oauth2.googleapis.com/token` and `/calendar/v3/calendars/`, with a `google_connection` settings row sealed by the dev `HEARTH_SESSION_SECRET`.
