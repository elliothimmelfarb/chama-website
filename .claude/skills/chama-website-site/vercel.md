# Vercel

- Read a redirect or header live before claiming it works: `curl -sI` against both `chamainteligente.com` and `www.`. A `/:path*` source does not match the bare root `/`, so a redirect written that way returned 200 on `/` for two weeks while the config looked right.
- Vercel's `[...path]` catch-all matches only one segment for plain (non-framework) functions. That is why `/api/hearth/*` is rewritten in `vercel.json` to the flat `api/hearth.js`, which routes internally.
- Scripts and stylesheets are versioned by content (`?v=`, README "Caching"); `npm run stamp` before committing, and `npm run check` names any stale address. Two traps found setting it up (2026-11-12): `vercel dev` ignores `has`/`missing` and every custom `Cache-Control` (it answers `max-age=0` for everything), so it cannot show the asset headers. `vercel build` can: `.vercel/output/config.json` lists the compiled header routes in the order they apply. And Vercel ignores the query string for static files at the edge, so `?v=` only busts the browser; that works because the edge cache is per deployment. Because Vercel never looks at `v`, the year-long rule matches only the tree's versions (a `has` query condition with `value: { inc: [...] }`, written by `npm run stamp`; 2026-11-12, from the security review): matching any `v` let a version computed from the public repo before its deploy pin an old body for a year. `vercel.json` can be checked against `https://openapi.vercel.sh/vercel.json` with ajv before a deploy, but only a live read shows the edge applies it: `curl -sI` a page's own `?v=` address (immutable) and `?v=0000000000` (`max-age=0`).
- The `/api/chat` rate limit (10 per IP per minute) is a Vercel Firewall rule in the dashboard. It is not in this repo, so grep will not find it.
