# Vercel

- Read a redirect or header live before claiming it works: `curl -sI` against both `chamainteligente.com` and `www.`. A `/:path*` source does not match the bare root `/`, so a redirect written that way returned 200 on `/` for two weeks while the config looked right.
- Vercel's `[...path]` catch-all matches only one segment for plain (non-framework) functions. That is why `/api/hearth/*` is rewritten in `vercel.json` to the flat `api/hearth.js`, which routes internally.
- Scripts and stylesheets are versioned by content (`?v=`, README "Caching"); `npm run stamp` before committing, and `npm run check` names any stale address. Two traps found setting it up (2026-11-12): `vercel dev` ignores `has`/`missing` and every custom `Cache-Control` (it answers `max-age=0` for everything), so it cannot show the asset headers. `vercel build` can: `.vercel/output/config.json` lists the compiled header routes in the order they apply. And Vercel ignores the query string for static files at the edge, so `?v=` only busts the browser; that works because the edge cache is per deployment. Read the headers live: `curl -sI 'https://chamainteligente.com/assets/worlds.js?v=x'`.
- The `/api/chat` rate limit (10 per IP per minute) is a Vercel Firewall rule in the dashboard. It is not in this repo, so grep will not find it.
